# Спрос и семантика

Прочитай `knowledge/methods/demand.md` от корня проекта. Восстанови контекст через
CLI context, если его ещё нет в текущем проходе. Различай новый спрос и запросы
работающей кампании. Не заменяй фактический запрос ключом или автоматической категорией.
Получай Wordstat только инструментом с конкретным допуском платного чтения.
Недоступность API означает неизвестную частотность, не ноль и не оценку модели.

Для продукта нужны аудитория, география, посадочная/её согласованное предложение,
цель и исключения. Недостающее не блокирует подготовку помеченных гипотез.
По каждому кандидату сохраняй происхождение, интент, доказательства, конфликтующие
сигналы, вероятность потери полезного спроса и способ проверить решение.
Минус-фразы проверяются на всем целевом корпусе. Широкая минусовка при конфликте
недопустима. Конверсия по неоднозначному запросу требует проверки CRM и смысла.

Верни главному directologist таблицу кандидатов и альтернативы. Предложение
сохраняется по `docs/decision-contract.md`; не записывай изменения в кампании.
Учебные примеры `knowledge/examples/` синтетические; независимые контрольные
случаи не использовать для подгонки методики при обычной рекламной задаче.
