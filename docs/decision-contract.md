# Предложение решения

Сначала `context`; взять project_id/context_hash и knowledge.version.
`propose --input /absolute/path/decision.json` проверяет и сохраняет в SQLite.
Это предложение, не API-вызов. Значения ниже — структура, не реальное заключение.

```json
{
  "schema_version": 1,
  "project_id": "my-project",
  "context_hash": "HASH_FROM_CONTEXT",
  "knowledge_version": "VERSION_FROM_CONTEXT",
  "methods": ["diagnosis"],
  "status": "INSUFFICIENT_DATA",
  "evidence_ids": [],
  "facts": [],
  "hypotheses": ["Возможен разрыв между рекламным событием и реальным лидом"],
  "alternatives": ["Наблюдение без изменения кампании", "Проверить настройку цели и CRM-связь"],
  "uncertainty": ["Нет проверенного отчёта и связи с CRM"],
  "expected_outcome": "Получить данные для сравнения, бизнес-эффект пока неизвестен",
  "evaluation_window": "Определить по периоду отчёта и лагу CRM до эксперимента",
  "next_step": "Подключить источники через setup и получить согласованный read-only отчёт"
}
```

Статусы: PROPOSED, OBSERVE, INSUFFICIENT_DATA, REVIEW_REQUIRED, OWNER_REQUIRED.
Без evidence доступны только последние три. Факт — объект с `text` и
`evidence_id` из списка проверенных артефактов. Методики diagnosis/demand/ads.
Хеш знаний включает файлы методик и активную версию проектных уроков; изменение требует повторной проверки.
Валидация доказывает структуру и наличие свежего evidence, а не истинность
произвольного текста или причинности: это предмет содержательного ревью.
`context` показывает до пяти сохранённых решений и незавершённые операции.
Устаревшие решения сохраняются для истории, но не становятся новым допуском.
Личные сведения и секреты не помещать в текст предложений; универсального DLP нет.

Если одновременно нет данных и требуется решение владельца, выбери
OWNER_REQUIRED и перечисли пробелы отдельно. REVIEW_REQUIRED — противоречивые
сигналы, INSUFFICIENT_DATA — отсутствие достаточных входов без конфликта прав.
В evaluation_window отдельно назови ближайшую диагностическую проверку и,
если эксперимент предложен, его окно; не выдумывай срок завершения без условий.
Пользовательские вводные, не зарегистрированные как evidence, сохраняй явно
как вводные в объяснении/неопределённости, не как facts с фиктивным ID.
