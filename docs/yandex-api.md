# Подключение Яндекс Директа

Проверено 12 ноября 2026. Новый локальный клиент: `scripts/yandex_direct.py`, стандартная библиотека Python, без импорта старого движка и без новых зависимостей. Это клиент API, не новый MCP-сервер.

## Что подключено

Используется существующая запись macOS Keychain, на которую ссылается `config/yandex-connection.json`. Токен не копировался, не менялся и не сохранялся в проект. Старая строка namespace Keychain — адрес секрета, а не зависимость от прежнего кода. Подключение Директа реально подтверждено чтением. Метрика и Wordstat подключены следующим отдельным поручением: [инструкция и проверка](metrika-wordstat.md).

В конфигурации `writes_enabled: false` отражает прямое поручение «рекламу пока не меняй». Это временный режим, не ограничение функционального каталога. Сейчас не включать запись. Будущее поручение на запись должно определить реальные объекты и действие; наличие прав в API не заменяет такое поручение.

## Каталог и охват

[Каталог](yandex-api-catalog.md) и `config/yandex-direct-methods.json`: 23 текущих RPC-сервиса, 87 методов (27 чтения, 60 записи), отдельно Reports. Источники каждого метода и ограничения провайдера сохранены рядом. Снятые методы отделены и не вызываются как действующие. Каталог проверен по документации и публичным схемам; это не заявление о полном доступе текущего аккаунта ко всем функциям интерфейса Яндекса.

По умолчанию используется v501, в частности для ЕПК. Публичные схемы v5 также проверены, но live-проверка выполнена только через v501. Для нового метода обновляется каталог с официальным источником и типом действия; неизвестный метод не считается безопасным чтением автоматически.

Клиент сохраняет все переданные параметры, не вводит собственных схем кампании, лимитов числа групп, объявлений, ключей, срока работы и суточных операций. Он также не проставляет автоматически возраст, устройства, цели, бюджет или стратегию. Правильность конкретных полей проверяется по документации метода и ответу Яндекса. Метод `prepare` готовит тело запроса, но не является серверной валидацией.

## Использование агентами

Рабочий каталог — корень нового проекта. Каталог функций:

```sh
python3 scripts/yandex_direct.py catalog
```

Передай параметры из JSON-файла. Например, для Clients.get достаточно:

```json
{"FieldNames":["Currency","Restrictions","AvailableCampaignTypes"]}
```

```sh
python3 scripts/yandex_direct.py prepare --service Clients --method get --params /absolute/path/params.json
python3 scripts/yandex_direct.py call --service Clients --method get --params /absolute/path/params.json
```

`prepare` не читает ключ и не обращается в сеть. `call` читает Keychain непосредственно перед запросом; стандартный вывод содержит статус, RequestId и путь результата. Полные ответы и журнал по умолчанию сохраняются вне Яндекс.Диска в `~/.local/share/1pi-directologist4/`. Не направлять ответы с персональными данными в синхронизируемый проект. В проекте оставлять только нужные обезличенные итоги.

Пакеты формирует оператор по ограничению конкретного метода из каталога, а не по общей константе движка. Постраничная выборка управляется вызывающим агентом: проверять `limited_by`/`LimitedBy` и продолжать по схеме метода. `OK` означает принятую страницу, не полную выгрузку. Клиент не ограничивает число страниц самостоятельно.

Для Reports используется `--service Reports --method get`, где get — только имя операции CLI: в Яндекс отправляется тело с `params`, без `method`. Заголовки отчёта можно передать JSON-файлом через `--report-headers`: processingMode, returnMoneyInMicros, skipReportHeader, skipColumnHeader, skipReportSummary. Ответ PENDING сохраняет retryIn; повтор получения отчёта выполняется после ожидания с теми же параметрами. Клиент не опрашивает очередь автоматически. Пустой отчёт не считать доказательством отсутствия рекламных результатов вне выбранного периода и фильтров.

Для AgencyClients заголовок Client-Login не отправляется. Для addPassportOrganization предусмотрен Member-Authorization из отдельной ссылки `direct.member_credential` на Keychain; этот путь проверен только локально, второй ключ не подключён. Опциональный `use_operator_units: true` предназначен для агентского аккаунта по документации, сейчас не включён.

## Исполнение и результаты

Транспорт способен сформировать запросы всех методов каталога. Для реальной записи нужны изменённое действующее поручение, включённый режим записи и явные `--execute-write --operation-id <id>`; сейчас они не используются. Старые grants, SHA-разрешения, сроки и квоты не импортированы.

Перед запросом журналируется STARTED с локальным operation_id и хешем тела. Повтор того же ID записи блокируется. После ответа сохраняются статус и RequestId; пообъектные результаты остаются в приватном ответе. Автоповторов нет. UNKNOWN сначала сверять по фактическому состоянию; новый ID не является способом повторить неизвестную операцию. Локальный журнал не делает API провайдера идемпотентным.

PARTIAL и даже OK не означают принятия каждого запрошенного объекта: оператор сопоставляет весь исходный пакет с результатами и выполняет readback. Автоматического общего сборщика кампаний и универсальной сверки пообъектных записей в этом тонком клиенте нет. Технические возможности записи не проверялись живыми изменениями.

## Подтверждённая проверка

[verification.json](../work/yandex-connection/verification.json): 34 реальных вызова чтения; 25 из 27 RPC-методов чтения и Reports успешно ответили. Для ограниченных объектов выбрана одна наблюдённая неархивная кампания; для списков аккаунта проверены выбранные поля. Это не полная инвентаризация всех объектов и сочетаний параметров.

- AgencyClients.get: ответ Яндекса 54, «Нет прав для доступа в агентский сервис». Ограничение текущего аккаунта, не клиента.
- AdVideos.get: нужен реальный upload ID. Первичный запрос без него получил 8000; видео ради проверки не загружалось. Метод присутствует в каталоге, полноценное чтение статуса видео не подтверждено.
- Первичные ошибки ещё шести запросов исправлены по официальным схемам: обязательные Levels, Id вместо CreativeId и отсутствие optional SelectionCriteria вместо пустого IdsCriteria. Повторные исправленные чтения прошли; исходные ошибки не скрыты в evidence.
- Reports: протокол ответил 200; в выбранном отчёте только заголовок. Это не коммерческий вывод.
- 17 локальных тестов проходят, включая блокировку записи до Keychain/сети, отсутствие фильтрации новых полей, обрыв HTTP, UNKNOWN, частичные ответы, заголовки агентства и Reports. Все 88 операций каталога (87 RPC + виртуальный Reports.get) локально формируют транспортное тело без Keychain; пустые учебные параметры не являются валидными payload провайдера.

Команда проверки: `python3 -m unittest discover -s tests -v`.
