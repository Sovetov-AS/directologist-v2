# Подключения

Создайте свой проект по README, затем запустите в пользовательском терминале:

```sh
.venv/bin/python scripts/directologist.py --project my-project setup
```

Мастер последовательно предлагает Директ, Метрику, Wordstat и CRM bridge.
Каждую площадку можно пропустить. Ключ вводится скрыто в TTY, без аргументов и
environment. Выберите свои ресурсы из проверенного списка: кабинет и кампании,
счётчик и цели, cloud folder и регионы либо CRM portal.
Система не выпускает ключи API: их предоставляет пользователь с нужными правами.

Хранилище выбирается явно: macOS Keychain, Windows Credential Locker или Linux
Secret Service. Отказ ОС не заменяется plaintext backend. В Linux нужна desktop
DBus/Secret Service-сессия. API-права и подписка площадки проверяются отдельно.
Native OS acceptance выполняется в среде пользователя; CI использует подмены.

## CRM bridge

Нужен отдельный совместимый read-only bridge. Этот репозиторий не разворачивает
bridge и не подключается к Bitrix24 напрямую. До setup создайте локальный
`projects/my-project/allowed-services.json`:

```json
{"schema_version":1,"crm_origins":["https://bridge.example.org"]}
```

`example.org` — пример, замените на согласованный HTTPS origin своего bridge.
Без allowlist ключ не запрашивается. Нельзя указывать путь, пароль, query или fragment.
Контракт каталогов и сводки реализован в `scripts/directologist/adapters/`;
совместимость со своим bridge нужно проверить до анализа результатов.

## Состояние и восстановление

```sh
.venv/bin/python scripts/directologist.py --project my-project connections status
.venv/bin/python scripts/directologist.py --project my-project connections recover
```

`status` показывает сохранённую проверку и её время, не обращается к ключам/API.
`CHECKED` означает успешный каталог ресурсов в тот момент, а не общую API-приёмку.
Новая настройка повышает binding_version; прежние задания с устаревшим контекстом
не продолжаются. Необходим новый анализ и план.

Настройка сначала фиксирует SQLite, затем атомарно публикует профиль. После сбоя
`recover` допубликует сохранённую версию, если пользователь не изменил профиль вручную.
Ручное редактирование SQLite не является процедурой восстановления.

При повторной настройке вводите ключ заново. Старые записи ОС автоматически не
удаляются: их могут использовать резервные копии. Namespace для совместимости:
`pro.1pi.directologist.v2/<project_id>/<provider>`, account — connection_id.
Название namespace не подключает вас к какому-либо чужому аккаунту.
Очистку выполняйте средствами ОС после проверки резервных копий.

Во время технической операции ключ находится в памяти Python. Защита от процесса,
имеющего произвольный shell под тем же пользователем, не доказана. TLS проверяется;
редиректы и proxy из environment отключены. Ошибки поставщиков не печатают raw body.
Изменение рекламы через эти адаптеры недоступно.
