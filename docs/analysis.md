# Данные и расчёты Директолога

Технический слой получает отчёты и проверяет контекст перед расчётами.
Локальные тесты используют синтетические проекты и ответы. Реальные API требуют
отдельной приёмки в аккаунте пользователя. Команд изменения рекламы нет;
методики рассуждения находятся в knowledge/methods/.

## Что доступно

| Источник | Отчёт | Существенная граница |
|---|---|---|
| Direct | По дням и выбранным кампаниям: показы, клики, расход, конверсии одной явной цели | Валюта получена из clients.get; цель, атрибуция и НДС сохраняются |
| Метрика | Итоги по счётчику: визиты и достижения выбранной цели | Весь трафик сайта; отчёт не считается трафиком Директа |
| CRM bridge | Агрегаты лидов, квалификации, выигранных сделок, выручки, маржи и качества данных | Когорта по дате создания лида/сделки с текущим состоянием; чтение только через разрешённый bridge |
| Wordstat | Технический адаптер topRequests и локальная очередь | CLI только готовит очередь и показывает состояние; платный runner ещё не включён |

## Сбор и анализ

После `setup` источник должен иметь CHECKED, актуальные привязки и ключ в хранилище ОС.
Команды ниже — шаблоны для согласованного чтения. `GOAL_ID`, даты и `EVIDENCE_ID`
нужно заменить фактическими значениями; исторические цели v1 не подставляются.

```sh
.venv/bin/python scripts/directologist.py --project my-project collect \
  --source direct --date-from 2026-09-01 --date-to 2026-09-07 \
  --goal GOAL_ID --attribution AUTO --vat excluded

.venv/bin/python scripts/directologist.py --project my-project collect \
  --source metrika --date-from 2026-09-01 --date-to 2026-09-07 \
  --goal GOAL_ID --attribution last

.venv/bin/python scripts/directologist.py --project my-project collect \
  --source crm --date-from 2026-09-01 --date-to 2026-09-07

.venv/bin/python scripts/directologist.py --project my-project analyze \
  --evidence EVIDENCE_ID
```

Direct поддерживает AUTO/FCCD/LC/LSCCD; Новый сбор Метрики — automatic/last. Устаревшие first/lastsign
не отправляются: отключение старых моделей обнаружено при сверке официальной
документации 2026-09-18. Исторические evidence сохраняют своё обозначение.
Они сохраняются в собственных обозначениях источников. TTL отчёта по умолчанию
3600 секунд, меняется через `--ttl-seconds` в пределах 1–86400.

Если Direct вернул отложенный отчёт, CLI возвращает состояние PENDING и интервал
повтора. При квоте — QUOTA. Повтор той же команды до срока не читает Keychain
и не вызывает отчёт снова. Название отчёта детерминировано параметрами; повтор
после срока запрашивает тот же отчёт. Нет фонового опроса или скрытого ожидания.
HTTP-ошибки и исходные ответы с секретами не печатаются.

`analyze` принимает несколько `--evidence`. Direct-части объединяются только
при совпадении проекта, версии привязок, периода, цели, атрибуции, области,
единиц, полноты и семплирования; пересекающиеся строки отклоняются.
Отчёты разных источников показываются рядом, по одному отчёту на источник.
Разные периоды и контексты проекта отклоняются. Между источниками суммы
не складываются: `cross_source_attribution=NOT_ESTABLISHED`, `crm_cpl=null`,
`cac=null`. Даже равные числа конверсий и лидов не доказывают связь событий.

## Контракт EvidenceBundle v1

Каждый файл включает версию схемы, project_id/context_hash, источник, период,
цель, атрибуцию, область отчёта, единицы денег и НДС, полноту, семплирование,
время получения, срок годности, строки и SHA-256. Неизвестные поля запрещены.
`timezone` — пояс проекта; `source_timezone=null` явно означает, что пояс
и границы суток источника пока не подтверждены адаптером. При live-приёмке
нужно отдельно сверить часовые пояса, задержки конверсий и обновления CRM.
TTL измеряет возраст получения ответа, а не доказывает свежесть учётной системы.

`COMPLETE` означает полный принятый набор строк ответа, а не полноту CRM,
правильность целей или доказанную атрибуцию. Для CRM отдельно сохраняются
число недостающих настроек, несопоставленные лиды и сделки без связи с лидом.
`sampled=true` и `sampled=null` остаются видны потребителю; полнота выборки
не выдумывается. При PARTIAL/UNKNOWN итоговые суммы не выдаются как полные.

Расчёты выполняются Decimal с точностью 64 знака. Float на входе запрещён;
числа JSON API читаются Decimal, в evidence хранятся десятичные строки.
Отсутствие (`null`, пусто, `--`) не превращается в ноль. Если в показателе есть
пропуск, его итог и зависимые коэффициенты неизвестны. CTR/CPC/CR считаются
из сумм; нулевой знаменатель даёт null. Коэффициенты округляются до 6 знаков,
ROUND_HALF_EVEN. Стоимость рекламной конверсии называется
`cost_per_ad_conversion`, чтобы не выдавать её за стоимость CRM-лида.
Выручка и маржа сохраняются отдельно по валютам; пересчёт валют отсутствует.
Decimal не исправляет возможное округление внутри внешнего CRM bridge.

Отчёты сохраняются в `projects/<id>/artifacts/evidence/<sha256>.json`, индекс —
в SQLite. Размер сохранённого evidence ограничен 1 MiB: большой отчёт требует
меньшего периода/области, автоматического усечения нет. SHA-256 обнаруживает
изменение, но не удостоверяет доверие к автору. Истёкший отчёт, другой проект,
прежняя версия привязок, повреждённый файл или символьная ссылка отклоняются.

Экспорт `analyze` содержит контекст, итоги и признаки качества; не сырые строки.
CRM names/phones/emails/UTM, индивидуальные leads/deals и неизвестные поля
отбрасываются до сохранения evidence. Это структурная минимизация, а не
универсальный поиск персональных данных в произвольном тексте.

## Очередь Wordstat

Пример локального JSON-пакета (условная фраза, не реальные результаты):

```json
{
  "schema_version": 1,
  "request_limit": 10,
  "ttl_seconds": 3600,
  "requests": [
    {"phrase": "тестовый запрос", "regions": [225], "devices": ["all"], "num_phrases": 10}
  ]
}
```

```sh
.venv/bin/python scripts/directologist.py --project my-project wordstat enqueue \
  --job-id research-example --input /absolute/path/wordstat-input.json
.venv/bin/python scripts/directologist.py --project my-project wordstat status \
  --job-id research-example
```

`enqueue` и `status` могут создать локальные таблицы очереди; API не вызываются.
`live_runner_enabled=false`. Внутренний Python callback `WordstatReader` и
`WordstatQueue.step` предназначен для будущего исполнителя с согласованным
допуском на платное чтение. Сама очередь не является механизмом выдачи допуска.
Текущий CLI не предоставляет live-команду исполнения или ручного повтора.

Ключ кеша включает контекст проекта/привязок, нормализованную фразу, регионы,
устройства и число фраз. Регистр/пробелы/ё нормализуются. Совпавшие запросы
дедуплицируются; готовая задача не выполняется повторно. Новый пакет может
использовать свежий кеш. При истечении кеша готовая задача остаётся DONE с
`cache_fresh=false`; для нового исследования нужен новый job_id.
Изменение параметров существующего job_id запрещено.

Перед callback попытка и расход квоты записываются в SQLite. Лимит попыток
пакета и интервальные лимиты действуют после перезапуска. QUOTA сохраняет
retry_at; работа возобновляется после него. После сбоя RUNNING становится
UNKNOWN при следующем `step`; весь этот пакет останавливается до явной сверки.
`retry_unknown` — внутренняя точка продолжения после сверки; она не обнуляет
счётчик попыток. Одновременные workers одного проекта блокируются файловой
блокировкой. Сроки и ответы с неопределённым результатом не считаются нулевыми.

Кеш Wordstat содержит технические фразы, которые могут включать персональные
данные. Он не предназначен для автоматического экспорта модели; статус
выдаёт только ключи, состояния и сроки, без фраз и ответов. Шифрования SQLite
нет. Лимиты очереди действуют для проекта, а не для других программ с теми же
credentials; общий провайдерский лимит требует отдельной координации.

## Восстановление и проверка

`backup` копирует SQLite, включая очередь, её кеш, индекс evidence и задержки
отчётов. Файлы evidence и профиль в эту копию не входят: для полного сохранения
аналитических материалов их нужно копировать отдельно. После восстановления
БД без файлов индекс сам по себе не восстанавливает отчёты. Восстановление
старой копии может потерять последние попытки платных запросов; до нового
исполнения необходима сверка с внешним результатом.

```sh
.venv/bin/python -B -m unittest discover -s tests -p 'test_*.py' -v
```

API credentials в тестах синтетические, проекты временные, сеть блокируется.
Запуск платного Wordstat, реальный отчёт и бизнес-результат тестами не доказаны.

## Происхождение решений

Использованы собственные v1: Reports metadata и выбранные goal/attribution,
раздельные агрегаты CRM bridge, нормализация/кеш/квоты Wordstat. Источники методик — `knowledge/sources.json`. Новый код не импортирует v1
и не наследует его credentials, ресурсы или разрешения. В v2 добавлены строгий
контекст evidence, Decimal, явное UNKNOWN и минимизация данных до экспорта.

Формат Direct (денежные значения по умолчанию в миллионных долях, заголовки,
retryIn): [Reports headers](https://yandex.com/dev/direct/doc/en/headers),
[отложенный режим](https://yandex.ru/dev/direct/doc/reports/mode.html).
Формат Wordstat: [topRequests](https://aistudio.yandex.ru/ru/docs/search-api/operations/wordstat-gettop).
Эти контракты проверены локально на синтетике; совпадение с конкретным живым
аккаунтом требуется подтвердить отдельно.
