# Подключение Метрики и Вордстата

Проверено 12 ноября 2026. Клиент — `scripts/yandex_data.py`, стандартный Python без новых зависимостей. Он использует только общие утилиты нового клиента Директа; старый движок не импортируется. Существующие отдельные ключи Метрики и Wordstat читаются из macOS Keychain по ссылкам в `config/yandex-connection.json`, не копируются в проект.

## Кому принадлежит работа

| Инструмент | Основной исполнитель | Задача |
|---|---|---|
| Метрика | Директор, `agency-director` | Посещаемость, источники, цели, конверсии, сопоставление с Директом; чтение настроек и статусов интеграций |
| Wordstat | Семантик, `demand` / `agency-demand` | Частотность, формулировки, сезонность, региональное распределение и классификация спроса |
| Технические изменения Метрики | `direct_operator` по конкретному поручению директора | Настройки/цели/импорты; сейчас не выполняются |

Маркетолог получает выводы и источники от директора/семантика, дизайнер — бриф. Не нужно запускать одинаковые исследования от каждой роли. Это распределение работы, не запрет директору сделать короткую проверку самостоятельно.

## Возможности

- [Каталог Метрики](metrika-api-catalog.md): 110 опубликованных операций, в том числе отчёты, счётчики/цели/сегменты/фильтры/доступы, Logs, импорты расходов/CRM/звонков/чатов/офлайн-конверсий и Measurement Protocol. Одна противоречивая страница chat-list не исполняется; есть корректный общий список офлайн-загрузок. JSON — `config/yandex-metrika-methods.json`.
- [Каталог Wordstat](wordstat-api-catalog.md): все 4 метода текущего WordstatService. JSON — `config/yandex-wordstat-methods.json`.

Клиент передаёт произвольные документированные query/body, не ограничивает метрики, цели, группировки, даты, размер исследования или локальное число запросов. Возможны JSON, сырое тело, multipart-загрузка; ответы JSON, CSV и бинарные выгрузки. Допустимые комбинации и размеры определяет Яндекс. `prepare` проверяет маршрут и готовит запрос без ключа/сети, но не заменяет серверную проверку полей.

## Использование

Запускать из корня нового проекта, даже если чат открыт в старом. Файлы параметров — обычный JSON; секретные поля туда не писать.

```bash
python3 scripts/yandex_data.py metrika catalog
python3 scripts/yandex_data.py wordstat catalog
python3 scripts/yandex_data.py metrika call --operation management_counter_counters
python3 scripts/yandex_data.py metrika call --operation management_goal_goals --path-params /absolute/path/counter.json
python3 scripts/yandex_data.py metrika call --operation stat_data_1 --query /absolute/path/report.json
python3 scripts/yandex_data.py metrika call --operation stat_data_1 --variant csv --query /absolute/path/report.json
python3 scripts/yandex_data.py wordstat call --operation getRegionsTree --body /absolute/path/empty-object.json
python3 scripts/yandex_data.py wordstat prepare --operation getTop --body /absolute/path/top.json
```

`counter.json`: `{"counterId":102018176}` — счётчик 1pi.pro подтверждён текущим списком; перед чужой задачей не выбирать его автоматически. `report.json` для проверки: `{"ids":102018176,"metrics":"ym:s:visits","date1":"2026-11-11","date2":"2026-11-11","accuracy":"full"}`. Рабочий период и цель определяются задачей; ID целей брать из свежего списка, не из старого навыка.

Платный запрос Wordstat выполняется тем же `call` с `--execute-paid --operation-id <уникальное-имя>`; эти аргументы отмечают осознанный платный вызов в журнале, а не требуют нового согласования каждого запроса. Работай в пределах текущего поручения на исследование и расходов. В текущем поручении выполнены только три платные пробы подключения; массовое исследование не запускалось. Тела всех четырёх проб сохранены в `smoke_body` каталога. В рабочем Top выбирай подходящий `numPhrases` вплоть до разрешённого Яндексом; `1` в пробе — размер тестового ответа, не квота клиента.

Сырые результаты, контекст запросов и журнал сохраняются вне Яндекс.Диска в `~/.local/share/1pi-directologist4/`, файлы с правами 0600. В stdout — статус/идентификатор/метаданные, без содержимого статистики и секретов. В проект переносить нужный итог, не сырые выгрузки. Не направлять приватные ответы через `--output` в синхронизируемую папку. Бинарный ответ хранится в `response.data_base64`, декодируется без изменения байтов.

## Полнота и ошибки

Клиент не делает автоматических повторов, обхода квот или скрытого обхода всех страниц. Для Метрики используй соответствующие методу `offset`/`limit` или `page`/`per_page`, сверяй итоговое число строк. `total_rows`, `sampled`, `sample_share`, `sample_size`, `sample_space`, `data_lag` сохраняются; HTTP 200 не доказывает полноту выборки и отсутствие семплирования. Для Wordstat сохраняются операторы, регион, устройства и период исходного запроса. Top не имеет API-пагинации и не является всем спросом.

При 429 сохраняется ответ и Retry-After; продолжение выбирается по реальной квоте/ошибке Яндекса. Не повторять платный UNKNOWN вслепую. Перед вызовом записывается STARTED, для платной операции и записи повтор того же operation_id блокируется. Новый ID не даёт идемпотентность и не доказывает, что прошлый запрос не был исполнен/оплачен. Явное `success:false` в HTTP 200 не считается успехом.

## Текущий статус Wordstat

**Яндекс сообщает о недоступности статистики после 7 октября 2026, хотя методы продолжают отвечать.** Перед новым исследованием проверяй [официальный статус](https://aistudio.yandex.ru/ru/docs/search-api/concepts/wordstat). Не подписывай Top/распределение как свежий спрос ноября по одному успешному ответу. Dynamics проверен за сентябрь 2026. Это не постоянный запрет дат клиента: после устранения причины на стороне Яндекса доступны его актуальные возможности.

По [тарифу](https://aistudio.yandex.ru/ru/docs/search-api/pricing) Top/Dynamics стоят по 0,02 ₽, распределение 0,05 ₽, дерево бесплатно. Три выполненные платные пробы дают расчёт 0,09 ₽; биллинг отдельно не сверялся. Реальная квота аккаунта не измерялась исчерпанием, старые собственные квоты не переносились.

## Запись и границы проверки

Сейчас `metrika.writes_enabled=false` и `direct.writes_enabled=false`. Настройки, цели, права, реклама и аналитические события не менялись; импорты, новые Logs-задачи и генерация секретов не запускались. Классификация основана на эффекте: POST Wordstat — чтение, GET генерации токена и GET Measurement Protocol — запись.

Для будущей разрешённой записи поддержаны соответствующие HTTP-методы, произвольные JSON/raw/multipart-тела, явный `--execute-write` и ID операции; право конкретного токена/формата и цикл запись→проверка остаются непроверенными. Общий ключ Метрики не подставляется вместо токена Measurement Protocol. Для MP и удаления его токена нужен отдельный `metrika.measurement_credential` в Keychain; сейчас он не подключён. Секретные query-поля подставляются только при вызове, не попадают в preview и журнал.

Проверенные живые вызовы, непройденное и локальные тесты — [verification.json](../work/metrika-wordstat-connection/verification.json). Проверка на одном счётчике и выбранных параметрах не означает проверку всех объектов, импортов или всей функциональности интерфейса. Коммерческие выводы по тестовым отчётам здесь не делались.
