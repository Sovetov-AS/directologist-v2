# Исторический контракт симуляции v1

Для реального ведения используйте [DirectGrant v2](autonomy.md). Ниже описан
сохранённый совместимый симулятор, его ограничения не относятся к исполнителю v2.

Поставляется механизм проверки с синтетической политикой SIMULATION. Реальная
политика проекта не создаётся автоматически. Параметры задаёт его пользователь:
ресурсы, разрешённые операции, поля/инварианты, общий бюджет на период, защитные
пределы платформы, лаг расхода, срок полномочий, отзыв и условия остановки.
Исторические бюджеты других пользователей не наследуются.

Поддерживаемый локальный контракт:
- версия и project/context, valid_from/expires_at (до суток), approval_source;
- точные resources и capabilities;
- max_reserved_micros: консервативный резерв суммы полных дневных бюджетов
  затронутых операций (кроме pause), не фактически потраченные деньги;
- max_operations: совокупный предел операций по версии допуска.

ChangePlan содержит SHA-256, project/context, policy_version, expires_at,
operations с id/capability/object_id/before/after/must_not_change/depends_on.
Снимок кампании: name, state ON/OFF, daily_budget_micros. Один объект — одна
операция в плане; зависимости только на предыдущие шаги. Создание только OFF;
resume отдельно, moderation не поддерживается. Все денежные значения — целые
микроединицы, валюта и платёжный период реального бюджета требуют будущего API-контракта.

Порядок: проверка → резерв и PREPARED → актуальный before → повторная проверка
версии/отзыва → STARTED в SQLite → callback → reread → CONFIRMED.
Расхождение postcondition даёт PARTIAL; потеря исхода — UNKNOWN. Перезапуск
записанного плана не отправляет шаги повторно. reconcile только читает и может
подтвердить фактический after. Наличие before после сбоя не доказывает, что
отложенный запрос не выполнится: такой исход остаётся UNKNOWN. Невыполненные
части не дописываются автоматически. Резерв не освобождается слепым повтором.

После восстановления backup запись блокируется. CLI `plan-validate` проверяет
только структуру симуляционного плана. Реальные операции используют отдельные
контракты DirectGrant/DirectPlan v2 и команды `direct`. Разделение предотвращает
случайное исполнение старых учебных планов на реальном аккаунте.
