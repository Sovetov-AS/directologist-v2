# Установка и работа

Система запускается в локальном Codex из каталога репозитория. Нужны Python 3.12+
и виртуальное окружение; команды установки приведены в README.
Навыки обнаруживаются в `.agents/skills/`. Аккаунты и правила поставляются пустыми.

Создайте проект с собственным ID, именем и часовым поясом:

```sh
.venv/bin/python scripts/directologist.py --project my-project project-create --name 'Мой проект' --timezone Europe/Moscow
.venv/bin/python scripts/directologist.py --project my-project setup
.venv/bin/python scripts/directologist.py --project my-project context
```

На Windows имя интерпретатора окружения — `.venv\Scripts\python.exe`.
`project-create` не перезаписывает существующий профиль. `setup` требует
пользовательского TTY; не передавайте ключи в чат, аргументы, environment или логи.
Права каждой площадки и ресурсы выбираются отдельно. Данные лежат только в
`projects/<id>/`; другой пользователь не получает их из репозитория.

Начните в Codex: «Настрой правила и самостоятельно веди рекламу проекта my-project».
Главный directologist выберет методику, вызовет расчёты и сохранит предложение.
Подробности: analysis.md, decision-contract.md, connections.md.
Для автономного ведения согласуйте DirectGrant v2 по [autonomy.md](autonomy.md).
Внутри действующих правил агент применяет изменения сам. Вне правил — OWNER_REQUIRED.

Остановка Codex прекращает будущие локальные действия, но не останавливает
показы в Директе. Платформенная остановка — отдельная операция. Восстановление
базы: backup/restore; ключи и JSON evidence требуют отдельного сохранения.
После восстановления сначала сверить незавершённые операции и состояние аккаунта.


## Сбои реального исполнителя

`direct status` показывает последние 50 шагов; `--request-id ID` — конкретный.
STARTED / ACKNOWLEDGED / UNKNOWN / PARTIAL блокируют обычные новые записи.
`direct reconcile --request-id ID` только перечитывает объект; если ответ создания
потерян до сохранения ID, сначала найдите объект в кабинете, сопоставьте все поля и
передайте `--object-id ID`. Не угадывайте ID и не создавайте дубликат с новым request_id.
Наличие старого before не доказывает, что запрос не выполнится позднее.

Сверка возможна по исходному сохранённому допуску после его отзыва или замены;
новой записи она не разрешает. Несовпадение after сохраняет блокировку. Не правьте
журнал вручную. Защитный `direct guard --stop` доступен и при незавершённых шагах.
После неизвестного создания без ID остановку такого объекта нельзя подтвердить
локально: найдите и при необходимости остановите его в кабинете.

Для прекращения ведения: `direct guard --stop`, проверить `stopped: true`, затем
`direct revoke` и остановить расписание. Отзыв сам по себе не выключает показы;
следующий guard распознает отзыв и попытается их остановить. При недоступном API
остановите кампании в интерфейсе Директа. Остановка приложения не выключает рекламу.

Backup сохраняет SQLite, но не профиль, JSON evidence/blueprints и ключи ОС.
Сохраняйте каталог проекта отдельно в приватном защищённом месте. Restore не
снимает `recovery_required`: потерянные после backup операции могут существовать
на платформе. Автоматическое возобновление writes после отката БД не поддержано.
Сначала остановите и инвентаризируйте рекламу, восстановите актуальный журнал из
полной копии либо подключите проверенные существующие кампании в новом проекте
с новым допуском. Старые файлы сборок при этом не запускайте заново.
